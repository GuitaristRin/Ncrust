# 小屏 / 矮屏 / 按键机适配调研

2026-10-15。触发：一位用户在荣悦 E5（3.49 英寸 320×480、ldpi，触屏 + 全键盘）上使用 Ncrust，「歌词部分几乎被纵向压没」。
同类设备还有负责人的 Walkman NW-F885（480×800 hdpi，见 `docs/f885-spike-report.md`；精简版另走 `walkman/` 分支工程，本调研只管主应用）。

## 方法

没有实机，用负责人的 Xperia 10 VII 模拟：`adb shell wm size / wm density` 临时改逻辑分辨率，截图后立即 `reset`（脚本 `D:/arcdeck/bin/ncrust-smallscreen.sh`，退出时必恢复）。
三档：**E5** 427×640 dp、**Walkman** 320×533 dp、**极限** 320×427 dp。对照：Xperia 10 VII 本身是 384×896 dp。
方向键用 `input keyevent DPAD_*` 注入。代码层面同时审读了布局分支与焦点处理。

## 结论先行

1. **全屏播放器在矮屏上是功能性故障，不只是不好看**：满宽方形封面盖住了进度条一整行（进度、时间、音质徽标）——用户**无法拖动、看不到播放位置**；
   歌名 / 歌手也被盖住；最矮一档连上一首 / 播放 / 下一首都被盖住，全屏播放器里**无法暂停**。
2. **歌词模式下歌词区只剩约 2 行**（E5 档）：歌词字号大、行距宽，控件区（时间行、进度条、60dp 大三键、切换行及其留白）占去近一半高度。
3. **列表页可用但浪费**：34sp 页头连上方留白约占 20% 高度；迷你条 56 + 底部导航 80 = 136dp 固定占用约 21%（640dp 高时）。Walkman 档一屏只见 2 首。
4. **方向键无可见焦点**：按下方向键画面毫无变化，用户不知道焦点在哪——对按键机等于不可用。代码里没有任何焦点 / 按键处理。
5. **根因**：所有响应式分支只看宽度（`screenWidthDp >= 600` 分手机 / 大屏），**没有任何按高度的分支**；`FullPlayerControls` 已有 `compact` 变体，窄屏手机从未使用。

## 设计方案（窗口尺寸驱动，不认机型）

### 1. 引入高度档

按**可用内容高度**（`screenHeightDp`，车机沿用现有实测高度逻辑）分三档，和现有的宽度判定正交：

| 档 | 高度 | 代表 |
|---|---|---|
| Regular | ≥ 720 dp | 普通手机（Xperia 10 VII 896dp） |
| Compact | 560–719 dp | 荣悦 E5（640） |
| Tiny | < 560 dp | Walkman（533）、更矮的按键机 |

做成一个 `CompositionLocal`（如 `LocalHeightClass`），各处只读档位，不各自拿数字比。

### 2. 全屏播放器（核心）

- **封面按可用高度定尺寸，不再强制满宽**（负责人确认：扁屏无法接受左右贴边的方形封面）：
  大封面边长 = `min(可用宽度, 可用高度 − 顶栏 − 控件区 − 最小留白)`，水平居中。Regular 档在普通手机上算出来仍是满宽，**外观不变**。
  实现上只改 `coverSizePx` 与 `largeCoverCenterY` 的取值来源（由测量得到，而不是 `screenWidth` 与 `screenHeight × 0.3`），
  封面的 progress / lyricAnimProgress 动画公式本身不动——AGENTS.md「cover always fills the full screen width」要相应改为「Regular 档满宽；矮屏按高度适配」。
- **控件区**：Compact 档用现有 `compact` 变体；Tiny 档进一步合并——进度条与时间压成一行，切换行（歌词 / 队列 / 收藏）的三个图标移进顶栏右侧。
- **默认模式**：Compact / Tiny 档在有歌词时默认进歌词模式（小封面在顶栏），大封面模式仍可手动切换。
- **歌词排版**：歌词字号与行距按档位缩小（需要 Kanesumi `MetroLyricsPanel` 支持字号参数——见「依赖」）。
- **验收标准**：三档下进度条、时间、三键、歌名都可见可操作；E5 档歌词区至少显示 5 行。

### 3. 列表页与外框

- 页头（34sp 大标题）在 Compact 档缩为约 24sp、Tiny 档并入一行紧凑标题，上方留白随之缩小。
- 底部导航：Compact 档高度 80→64dp；Tiny 档 56dp 且只显示图标（选中项显示文字）。`BottomOverlayInsetDp` 随之按档位取值。
- 迷你条保持 56dp（触摸目标），Tiny 档可去掉歌手行改单行。

### 4. 方向键 / 按键机

- **可见焦点**：所有可点项在键盘 / 方向键输入模式下显示 Kanesumi 风格焦点框（直角、2dp 主题色描边，无圆角、无阴影）。
- **焦点顺序**：列表上下、网格四向、底部导航左右；进入全屏播放器后焦点默认落在播放键；返回键 = 收起卡片 / 返回上一级。
- **数字键快捷**（设置可关）：5 播放 / 暂停、4 / 6 上 / 下一首、2 / 8 音量、0 打开 / 收起播放器；通话键 = 确认，挂断键 = 返回（以设备实际键码为准）。
- 触屏行为完全不变：焦点框只在按键输入模式出现。

## 依赖与风险

- **Kanesumi（负责人自有的外部库）**：焦点框最好在 `MetroIndication` 里统一实现（所有 `Metro*` 控件一次受益）；
  `MetroLyricsPanel` 需要字号 / 行距参数；`MetroBottomNav` 需要紧凑高度与仅图标模式。这三处要改 `Kanesumi-sec-a`——**需负责人决定**是改上游库，
  还是先在 Ncrust 侧包一层（焦点框可用 Ncrust 自己的 `Modifier` 实现，但覆盖不到 Kanesumi 控件内部）。
- **播放器卡片是 load-bearing 的手调动画**：只改封面尺寸与锚点的来源，不改动画公式；每档改完都要截图核对展开 / 收起 / 大封面↔歌词切换。
- **测试手段**：沿用 `wm size / density` 模拟三档 + 方向键注入；最好能请那位 E5 用户回测一个测试包。
- 与 Walkman 分支工程（`walkman/`）的关系：设计结论可共享（Tiny 档布局、焦点规范），代码不共享。
