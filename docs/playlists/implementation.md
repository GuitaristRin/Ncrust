# Android 歌单管理实施与验收

2026-10-28。按已确认的[交互约定](interaction.md)接入 Android。其他四条平台线尚未移植；远端协议证据见 [spec/api/playlists.md](../../spec/api/playlists.md)。

## 可用入口

先在用户页设置中打开「歌单管理（实验）」。`playlist_management_enabled` 缺省为 false；工作台约定要求真实账号未验证的新路径保留显式开关。

| 入口 | 行为 |
|---|---|
| 库 → 歌单 | 分页读取，自建/收藏分组，新建普通歌单 |
| 新建 / 编辑 | 名称（40 字以内）、简介（1000 字以内）、公开/私密；新建默认私密 |
| 歌曲菜单 → 添加到歌单 | 只选择本人普通歌单，也可以新建后加入 |
| 歌单详情 → 选择歌曲 | 全选或逐首选择，批量加入其他歌单；本人普通歌单可以批量移除 |
| 本人普通歌单详情 | 名称、简介和可见性编辑，单曲移除，单个删除确认 |
| 播放器队列 → 另存歌单 | 用队列曲目创建歌单，创建后逐批加入；不修改当前播放快照 |

八种运行时语言均补齐文案。布局使用 Kanesumi 控件；新增按钮根据背景亮度选择黑/白前景，并提供统一的按钮文字、角色、禁用和选中语义。

## 写操作边界

`PlaylistManager` 持有应用级任务，`PlaylistRepository` 组织读取权限、固定动作提交和读回确认。多字段修改分别执行，不假设服务端事务；每批曲目最多 500 个。

- 必须有有效账号，歌单作者为本人、普通类型且非 subscribed。未知作者或特殊类型不能写。
- HTTP 与业务码分别校验；仅添加解释 502 的重复语义，最终逐个 ID 读回确认。
- 结果区分确认完成、部分完成、待确认和失败。待确认只重新读取，不自动重放；创建没拿到 ID 时先检查歌单列表。
- 请求绑定发起凭证；限速等待后再次检查凭证。账号切换使旧响应失效，停止旧任务后续写入。
- 提交前按 UID 落盘显式 JSON 命令，不存 Cookie。进程重启后只恢复待核对状态；创建中途失去 ID 不猜测对应歌单。
- 关闭页面只隐藏任务。结束跟踪仅清除本地待核对记录，不撤销已经提交的云端变更。
- 删除前要求完整 ID 快照，备份名称、简介、可见性及全部曲目 ID，写入后 sync 并重新读取验证，失败则不发删除请求。文件位于应用内部 `files/playlist-backups/<pid>-<timestamp>.json`，结果页显示实际路径。
- 删除确认需完整本人歌单列表证明目标缺席；详情 404 本身不算成功。

备份是记录文件，不是自动恢复机制。封面上传、云端顺序拖拽、歌单文件夹、订阅/退订及批量删除歌单均未接入。批量写 API 已接线，但没有真实账号成功证据。

## 播放行为

歌单 `[A,B,C]` 点 B 后，队列保留原顺序，当前索引为 1。播放前核对完整 ID 快照与补齐的曲目顺序；缺曲目时保留旧队列并提示刷新。

普通歌单沿用当前普通模式；从私人 FM / INFINITY 转入时清 FM 标记、取消在途续播并切回 CYCLE。SINGLE 自然结束重复当前曲，手动下一首推进；LINE 队尾保留真实末曲并暂停；SHUFFLE 的预载、自然过渡和手动切换共用已准备的下一轮排列。整队不可播放时有界停止。云端编辑、移除或删除不改写正在播放的本地快照。
