# Android 播放列表管理实施与验收

2026-10-28。按已确认的[交互约定](interaction.md)接入 Android。其他四条平台线尚未移植；远端协议证据见 [spec/api/playlists.md](../../spec/api/playlists.md)。

## 可用入口

先在用户页设置中打开「播放列表管理（实验）」。`playlist_management_enabled` 缺省为 false；工作台约定要求真实账号未验证的新路径保留显式开关。

| 入口 | 行为 |
|---|---|
| 库 → 播放列表 | 无边框列表（64dp 封面贴左沿、无每行播放钮），自建/收藏分组，新建普通播放列表 |
| 长按任意歌单（库 / 首页推荐 / 搜索结果） | 自下而上的操作表（`PlaylistMenuSheet`）：播放全部 / 插播 / 最后播放；他人歌单加「收藏 / 取消收藏」；库里的本人歌单加「编辑信息 / 多选 / 删除」 |
| 操作表 → 多选 | 进入批量选择：标记画在封面上，工具条叠在列表顶端滑入（全选 / 删除 / 取消）；选择态里长按等同点按；删除逐个走备份+读回，进度在轻提示条，只有失败才弹汇总。收藏来的歌单压暗、不可选 |
| 他人歌单详情 → 收藏 | 页头首个按钮「收藏 / 已收藏」，与操作表同一条写入通道（见下「收藏他人歌单」） |
| 搜索 → 播放列表 | 第四个分类（`cloudsearch type=1000`），点按打开详情、长按出操作表，进入搜索历史 |
| 新建 / 编辑信息 | 名称（40 字以内）、简介（1000 字以内）、公开/私密；新建默认私密 |
| 歌曲菜单 → 添加到播放列表 | 底部面板，只列本人普通播放列表（带封面），也可以新建后加入；点中目标后面板收起、写入转后台 |
| 播放列表详情 → 编辑曲目 | 页头「编辑曲目」（他人歌单为「选择歌曲」）进入编辑态：点按切换封面上的选中标记；顶部工具条为 全选 / 加入其他播放列表 / 移除（仅本人） |
| 编辑态 → 拖拽手柄 | 本人完整歌单行尾出现手柄，按住拖动排序；顺序变化后工具条切换为「保存顺序」，选择动作暂停；整表提交（实验性，见下） |
| 普通态 → 左滑 | 本人歌单左滑单行露出「移除」，与菜单里的「从播放列表移除」走同一确认 |
| 本人普通播放列表详情 | 「编辑信息」改名称、简介和可见性；删除收在「⋯」菜单，走同一条批量删除通道（单个=批量 1 个），确认后返回列表 |
| 播放器队列 → 另存播放列表 | 用队列曲目创建播放列表，创建后逐批加入；不修改当前播放快照 |

编辑态的进入方式：歌单内**不用长按**（长按仍是歌曲菜单），由页头显式入口进入；编辑期间页头按钮原位压暗（不改变页头高度），改名/删除需退出编辑态。库里的歌单行长按与首页、搜索一致，弹出操作表；批量选择从表里的「多选」进入。

写入的反馈分三层：页内一次紧凑确认（取消 / 强调色铺底的确认格）→ `PlaylistManager.perform` 后台执行，`PlaylistNoticeHost` 轻提示条显示「正在同步」→ 已确认时提示条报告结果并自动收起（新建 / 加入可「查看」）。只有待确认、部分完成和失败才调出整页面板，面板只承载表单（新建 / 编辑信息）与核对结果。等待读回的待移除行先压暗，确认后由 `animateItem` 收起。

八种运行时语言均补齐文案。布局使用 Kanesumi 控件；新增按钮根据背景亮度选择黑/白前景，并提供统一的按钮文字、角色、禁用和选中语义。

## 写操作边界

`PlaylistManager` 持有应用级任务，`PlaylistRepository` 组织读取权限、固定动作提交和读回确认。多字段修改分别执行，不假设服务端事务；每批曲目最多 500 个。

- 必须有有效账号，播放列表作者为本人、普通类型且非 subscribed。未知作者或特殊类型不能写。
- HTTP 与业务码分别校验；仅添加解释 502 的重复语义，最终逐个 ID 读回确认。
- 结果区分确认完成、部分完成、待确认和失败。待确认只重新读取，不自动重放；创建没拿到 ID 时先检查播放列表列表。
- 请求绑定发起凭证；限速等待后再次检查凭证。账号切换使旧响应失效，停止旧任务后续写入。
- 提交前按 UID 落盘显式 JSON 命令，不存 Cookie。进程重启后只恢复待核对状态；创建中途失去 ID 不猜测对应播放列表。
- 关闭页面只隐藏任务。结束跟踪仅清除本地待核对记录，不撤销已经提交的云端变更。
- 删除前要求完整 ID 快照，备份名称、简介、可见性及全部曲目 ID，写入后 sync 并重新读取验证，失败则不发删除请求。文件位于应用内部 `files/playlist-backups/<pid>-<timestamp>.json`，结果页显示实际路径。
- 删除确认需完整本人播放列表列表证明目标缺席；详情 404 本身不算成功。

备份是记录文件，不是自动恢复机制。封面上传、云端顺序拖拽、播放列表文件夹、订阅/退订及批量删除播放列表均未接入。批量写 API 已接线，但没有真实账号成功证据。

## 曲目排序

排序没有独立端点，走 `manipulate/tracks` 的 `op="update"` 变体（官方 `I3()` 实证，语义仍是推断，见 [spec/api/playlist-edit.md](../../spec/api/playlist-edit.md)）。因为它是整表替换且「`op` 非 `add` 会被当删除」有实测记录，客户端加了三道闸：

1. 只在 `idsComplete` 且页面曲目与快照完全一致时提供入口；
2. 提交集合必须与当前曲目完全同集（同数量、同成员），否者直接拒绝，不发请求；
3. 提交前写 `files/playlist-backups/`，提交后一律重新读取并比对完整顺序，业务码（含 200/514/518）不参与成功判定。

排序在编辑态内用行尾拖拽手柄完成（`ReorderState`，不引入第三方库；靠近上下边缘自动滚动，并扣除顶部工具条与底部叠层的高度）；手柄另提供「上移 / 下移」无障碍动作。顺序一旦变化，逐首移除暂停，避免整表替换与逐首移除混在一次提交里。整表提交没有真机成功证据，入口仍受 `playlist_management_enabled` 约束。

## 播放行为

播放列表 `[A,B,C]` 点 B 后，队列保留原顺序，当前索引为 1。播放前核对完整 ID 快照与补齐的曲目顺序；缺曲目时保留旧队列并提示刷新。

普通播放列表沿用当前普通模式；从私人 FM / INFINITY 转入时清 FM 标记、取消在途续播并切回 CYCLE。SINGLE 自然结束重复当前曲，手动下一首推进；LINE 队尾保留真实末曲并暂停；SHUFFLE 的预载、自然过渡和手动切换共用已准备的下一轮排列。整队不可播放时有界停止。云端编辑、移除或删除不改写正在播放的本地快照。

## 2026-11-13 交互与动效重构

负责人反馈播放列表管理「操作逻辑和外观都比较糟糕」。本轮只改界面与反馈路径，不改云端协议、归属检查、备份与读回规则。

- 详情页：「编辑播放列表」+「管理▾」两个入口同名异义，拆为「编辑曲目」「编辑信息」两个平铺按钮，删除收进「⋯」；长简介默认三行、点按展开。
- 编辑态：统一为一个模式。选中标记画在封面上（`selectionMark`，draw 阶段读进度），不再为勾选框常驻 24dp 行尾槽位；工具条固定 56dp、图标化、自上方滑入，不再随选中数长出第二行；上/下箭头排序换成拖拽手柄。
- 写入：移除 / 保存顺序 / 选择器加入不再「确认对话框 → 第二个全屏面板再确认」，一次确认后后台执行；成功不再停在「已确认完成」页。
- 动效：面板宿主按呈现方式（选择器底部面板 / 整页）用单一进度位移 + 遮罩淡入，退场期间保留最后一帧；上游 `MetroDialog` 增加 SheetAppear 淡入上移（Kanesumi-sec-a 同日提交）。
- 对比度：强调色不再直接作浅色底上的文字色（云杉绿约 2.4:1）；主文字动作、确认格、新建入口改为强调色铺底、前景按亮度取黑/白。
- 修正：库里选择态长按会把已有选择重置为一项；选择态下系统返回会离开页面；歌曲菜单「添加到播放列表」误用了「转到专辑」的图标；「从播放列表移除」误用了「收藏」图标。

## 2026-11-13 歌单操作表、收藏与搜索

负责人在 Xperia 上试用后的反馈：库里歌单长按应是自下而上的操作列表而非批量操作；首页歌单应可收藏；搜索应有歌单类别。

- 操作表：`SongMenuSheet` 抽出共用的 `ActionMenuSheet`，新增 `PlaylistMenuSheet`（抬头为封面、名称、创建者、曲目数，无封面时放类型图标）。各页只提供本页特有动作，播放 / 队列 / 收藏由 MainScreen 统一追加，所以三处长按得到同一张表。
- 收藏他人歌单：`PlaylistAction.SUBSCRIBE / UNSUBSCRIBE`，eapi `playlist/subscribe` / `playlist/unsubscribe` + `id`，与其他写入同在实验开关后。写前读完整的「我的歌单」列表：本人或作者未知的歌单不提交，列表不完整不提交，已处于目标状态不提交；写后只认重新读取的列表（出现 = 已收藏；完整且不含 = 已取消），读不全为「待确认」，业务码只区分「被拒绝」与「待确认」。`PlaylistManager.library` 缓存这份列表供各页判断收藏状态，确认后先就地更新再补读。官方客户端的 `subscribe` 在 body 里带 `checkToken`，本端与其他歌单写入一样没有带，可能与旧收藏通道一样被事后回滚——只有真实账号写入后隔天复查才能确认。
- 搜索：`NcmApi.searchPlaylist`（type 1000）、`PlaylistSearchItem`（字段全部可空）、历史新增 `playlists` 键。四个分类在 320dp 窄屏下日语「アーティスト / プレイリスト」与俄语「Исполнители」会折行被裁，标签字号改为按宽度在 14 → 12sp 间取第一个全部单行的字号（`fittingTabStyle`）。

| 验收（Pixel_10 AVD，密度 320） | 结果 |
|---|---|
| `PlaylistMenuRenderingTest`（新增 3 项） | 操作表深浅色呈现、项目顺序、抬头、点按派发并收起；他人歌单页头只有收藏与选择歌曲，点按后变为「已收藏」；八种语言的四个分类标签按生产字号单行放下（首轮在 320dp 下抓到 3 个标签折行，修复后通过） |
